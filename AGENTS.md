# Notes for coding agents

SPIMquant is a Snakemake workflow packaged as a BIDS App (snakebids).
Entry point `spimquant/run.py`; CLI options, defaults and templates in
`spimquant/config/snakebids.yml`; rules in `spimquant/workflow/rules/`,
scripts in `spimquant/workflow/scripts/`. Environments are pixi
(`pixi run -e dev|gpu|docs ...`).

Before committing: `pixi run -e dev quality_check` (black, isort, snakefmt),
`pixi run -e dev pytest tests/`, and a dry run
(`pixi run spimquant tests/bids_ds /tmp/out participant -n`).

## Keeping the docs in sync

The docs (mkdocs, `docs/`) are mostly generated from the code. Know which
part is which before editing them.

### Generated at build time: never edit by hand

`docs/hooks.py` runs `docs/gen/build.py` before every build. It writes
these files (git-ignored):

| Page | Source |
|---|---|
| `docs/reference/cli.md` | the argparse parser (`spimquant/run.py`, i.e. `parse_args` in the config); analysis-level text from `docs/gen/descriptions.yml` |
| `docs/reference/templates.md` | `templates:` in the config + `descriptions.yml` |
| `docs/reference/config.md` | top-level config keys without a CLI option, described by the comment block above each key |
| `docs/reference/outputs.md` | `docs/generated/outputs.tsv` + `descriptions.yml` |
| `docs/reference/workflow.md`, `docs/reference/img/` | `docs/generated/rulegraph_*.dot` |
| `docs/examples/index.md` | `docs/examples/manifest.yml` |

So: to change the CLI reference, change the option's `help` in
`snakebids.yml`. To document a config key, write a comment above it.

### Regenerated by a command, committed, checked by CI

`docs/generated/` holds rule graphs and the list of every output file, from
dry runs of `tests/bids_ds` in the scenarios of `docs/gen/scenarios.yml`.
After changing rules, outputs or options that add outputs:

```bash
pixi run docs-introspect           # rewrites docs/generated/
pixi run -e docs docs-check        # lists anything undescribed
```

then describe new output suffixes, folders, templates or analysis levels in
`docs/gen/descriptions.yml` (a `folder/suffix` key overrides the description
in one folder) and commit both. A new optional output needs a scenario that
turns it on in `scenarios.yml`. CI (`docs` job in
`.github/workflows/test.yml`) fails if `docs/generated/` is stale, if
`docs-check` finds gaps, or if `mkdocs build --strict` fails.

### Example outputs: refreshed by hand from a full-resolution run

`docs/examples/` holds real QC reports, figures and table excerpts from one
full-resolution brain, listed in `docs/examples/manifest.yml`. The test
dataset (~100 µm) is too coarse for these; use a scan at about 2 × 2 × 4 µm
or finer. Refresh them when the look or content of a report, QC figure or
main table changes:

```bash
spimquant BIDS OUT participant --benchmark ...      # full-resolution run
spimquant BIDS OUT group ...
pixi run -e dev python docs/gen/collect_examples.py OUT \
    --dataset "..." --command "..."                 # rewrites docs/examples/
```

`collect_examples.py` picks the files by pattern, so a renamed output makes
it fail rather than silently skip; update its `ITEMS` list then. It also
prints the resource table for `docs/usage/running.md` (between the
`RESOURCES-TABLE` markers) from the run's benchmarks; paste it in.
Keep the assets small (the script downsizes PNGs); do not commit
full-resolution images.

### Written by hand: update with behaviour changes

Everything else: `docs/index.md`, `docs/getting_started/`,
`docs/workflow_overview.md`, `docs/usage/`, `docs/howto/`, `docs/faq.md`,
`docs/contributing.md`, and `README.md`. When you change behaviour, grep
these for the option, rule or file name and update them. Check in
particular:

- a new option or method: the guide for that area (`howto/segmentation.md`,
  `howto/registration_methods.md`, ...); `workflow_overview.md` if it adds a
  stage;
- a changed default: `getting_started/input_data.md` (stain lists),
  `usage/running.md`, `faq.md`;
- the quick-start command and its timing (`getting_started/quickstart.md`),
  if the test-dataset run changes;
- `README.md` stays short and points to the docs.

Style for hand-written pages: say what an option does, to which files, with
the numbers a user needs (units, defaults, run times). No marketing
adjectives, no paragraphs that restate the heading, no "TODO" placeholders
on published pages, and no option or file name that you have not checked
exists (`pixi run spimquant --help`, `docs/generated/outputs.tsv`).
